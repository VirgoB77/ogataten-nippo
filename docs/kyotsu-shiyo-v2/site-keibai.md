# 競売のサイト固有仕様（共通仕様 第2版の案）

**この文書は2つに分かれる。混ぜない。**

    【サイト固有の現在ルール】  いま効いている決まり。**正本（第2版）の一部として、競売に効く。**
    【実例・実測・経緯】        決まりではない。当時の日付・数・言い方のまま（いまの状態ではない）

競売の置き場へ正式に移すまでは、**ここがサイト別の決まりの置き場**。
取りに行ってよいかは、ここでは決めない（取りに行く前の門。§3.4）。
どちらも旧正本（第1版）の原文を**書き換えずに**写した。各段の頭の〔〕に、旧の行と節を書いた。

## 【サイト固有の現在ルール】

**〔旧 540〜541 行｜旧の節：法人だけの升は、1件でも伏せない ＞ ⚠️ これができるのは、**個票を全部出しているサイトだけ**｜サイト固有の現在ルール〕**

**競売統計（`records` が空）では、この例外を使わない。**


**〔旧 6057〜6059 行｜旧の節：守りを入れる日に、その守りが止めるものが、まだ要ることがある ＞ 例外には3つ要る｜サイト固有の現在ルール〕**

止まるものだけが残り続けない。競売統計では、印が公開用の木に混ざったら、
公開用の木を作るスクリプトが中断する形にした（印が届くと、公開用でも
自己停止が素通りするため）。

**〔旧 6098〜6098 行｜旧の節：守りを入れる日に、その守りが止めるものが、まだ要ることがある ＞ 例外が消えたあとの姿を、置いた日に試す｜サイト固有の現在ルール〕**

`run:` の本文を取り出し、名前と印を入れ替えながら実際に走らせる。

## 【実例・実測・経緯】（決まりではない）

**〔旧 5743〜5745 行｜旧の節：9. 技術方針（共通） ＞ 合計が変わらない壊れ方は、合計の検査では捕まらない｜実例・実測・経緯｜共通の本文：一般の決まりは本文に残した〕**

競売統計が踏んだ（2026-09-19）。過去データを入れると、升が
`公告-新規` から `公告-再公告` に**裏返る。**
だが**親（公告）の合計は変わらない**ので、「升の合計＝見た行の数」は通る。

**〔旧 5750〜5751 行｜旧の節：9. 技術方針（共通） ＞ 合計が変わらない壊れ方は、合計の検査では捕まらない｜実例・実測・経緯｜共通の本文：一般の決まりは本文に残した〕**

街頭窃盗統計も同じ形を書いている——「区画そのものが減ったとき。
**両方が同時に減れば釣り合う**」。

**〔旧 6032〜6036 行｜旧の節：9. 技術方針（共通） ＞ 守りを入れる日に、その守りが止めるものが、まだ要ることがある｜実例・実測・経緯｜共通の本文：本文には無い〕**

2026-09-19、競売統計で起きた。収集用は**置き場**。収集用の Actions は止め、
workflow は持たせない。その守りが「名前が `-raw` で
終わるか `-raw-` を含むリポジトリでは workflow が自分で止まる」。競売統計には
まだ入っていなかった。ところがその日、金庫がまだ唯一の集め手だった。金庫の名前は
既に `-raw` で終わっていて、公開用の Actions は鍵が未了で動かせない。素直に入れると、

**〔旧 6063〜6063 行｜旧の節：守りを入れる日に、その守りが止めるものが、まだ要ることがある ＞ 例外には3つ要る｜実例・実測・経緯｜共通の本文：本文には無い〕**

いまは `.github` が公開用の許可リストに無いので、この経路は一度も通らない。

**〔旧 6110〜6110 行｜旧の節：守りを入れる日に、その守りが止めるものが、まだ要ることがある ＞ 期限つきの例外を置いてよいのは、あとから直せる守りだけ｜実例・実測・経緯｜共通の本文：本文には無い〕**

金庫で Actions が走るのは置き場の形の話で、あとから直せる。取れなかった晩は直せない。
