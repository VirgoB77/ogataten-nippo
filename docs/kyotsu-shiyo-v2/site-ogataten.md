## 【サイト固有の現在ルール】

**〔旧 393〜398 行｜旧の節：3. 守ること（ハードルール） ＞ 3.1 個人情報｜サイト固有の現在ルール〕**

  大型店日報は、**住居系用途地域の個票を 207 件出している**。
  また、店名に住まいの語が入る**複合ビルが 12 件**ある
  （マンションや高層住宅の中に入っている店）。**どちらも伏せない。**
  対象が店舗で、当事者が法人で、建物には多数が住むため、
  **誰か一人の住まいにはならない**（2026-09-19、実測して決めた）。


**〔旧 872〜876 行｜旧の節：3. 守ること（ハードルール） ＞ 伏せる理由と、出さない理由は別｜サイト固有の現在ルール〕**

大型店日報が26年分の退店の一覧を作り、開店日までつながったのは3件だった（3.5）。
平均在店年数は出さないと決めた（2026-09-19）。個票を全部出しているので伏せても
守りにならず（6節）、伏せる側の理由は無い。それでも出さない。
3件の平均は、一覧全体について何も言っていない。


**〔旧 1309〜1310 行｜旧の節：コピーされることを、守りで解かない ＞ 欄はいま決める。**あとから過去は作れない**｜サイト固有の現在ルール〕**

大型店日報は `first_seen` / `last_seen` / `listed` / `mode` を持っていて、
**`index.json` には1つも出していない。** この形が正しい。

**〔旧 1451〜1452 行｜旧の節：3. 守ること（ハードルール） ＞ 予測を出すサイトは、予測の成績も出す｜サイト固有の現在ルール〕**

外れた結果も出すと先に決めてある（2026-09-19）。


**〔旧 1557〜1565 行｜旧の節：3. 守ること（ハードルール） ＞ 3.4 取得の作法｜サイト固有の現在ルール〕**

- **頻度は「中身の変わり方」と「相手が誰か」の両方で決める。**
  - 公報・告示など、発行されたら中身が変わらないもの → **月2回**
  - 縦覧一覧など、日々書き換わるもの → 毎日
  - 「掲載期間が3か月」なら、必要なのは「3か月以内に1回」であって毎日ではない。
  - **過去分の取り込み（積み直し）は例外。** 1日の上限（大型店日報の兵庫県公報は80号）・
    5秒・同時1本を守れば毎日でよい。追いついたら（未読が新着だけになったら）月2回に戻す。
    戻すのは人の手ではなくコードで（大型店日報は `koho_pdf.py` が未読20号以下になったら
    自動的に1日・15日だけにする。手で押したときは日に関係なく取りに行く）


**〔旧 2472〜2472 行｜旧の節：4. `common/addr.py` ＞ 町丁目で繋いだものは「同じ場所」ではなく「近い場所」｜サイト固有の現在ルール〕**

（大型店日報の退店一覧は `match` に「番地+店名」「町丁目+店名」と書く）。

**〔旧 3021〜3022 行｜旧の節：6. `index.json` ＞ 決まり｜サイト固有の現在ルール〕**

- 升の期間は、伏せ字だらけにならない粗さにする（3.2）。大型店日報は市区町村×種別×**年**。
  月にすると 3,713 升のうち 95% が `1-2` になった。月と年の両方は出さない（引き算で戻る）。

**〔旧 6257〜6263 行｜旧の節：9. 技術方針（共通） ＞ 登記所備付地図データ（法務省）― 規約の読み（統括判断 2026-09-21）｜サイト固有の現在ルール〕**

| 見たところ | 結果 | 逐語・要点 |
|---|---|---|
| ダウンロード・保存 | **取ってよい** | 複製を明示的に認めている。継続取得・自動取得という語は無いが、機械取得や保存の明示的禁止も無い |
| 加工・二次利用 | **取ってよい** | 編集・加工利用が規約上明示的に想定されている |
| 商用利用 | **取ってよい** | 規約本文に「商用利用も可能です」 |
| 出典 | **必須** | 「出典：「登記所備付地図データ ○○市」（法務省）（URL）（○年○月○日に利用）」。加工したときは加工したことも別に表示する |


**〔旧 6277〜6283 行｜旧の節：9. 技術方針（共通） ＞ 登記所備付地図データ（法務省）― 規約の読み（統括判断 2026-09-21）｜サイト固有の現在ルール〕**

**取るときに必ず残すもの（8つ）:**

  ・データセット名 ・市区町村 ・年度 ・元URL
  ・取得日 ・取得元データセットID ・ファイル名 ・SHA-256

推測で欠損を埋めない。低負荷で取る。
