**2026-09-26 時点**

## 何をしているか

個人事業で、**日本の行政が公表している一次情報を、そのまま保存している**（1日1回まで）。
**2026-09-25 から、自動の取得の多くを、安全確認のため一時停止している**（廃止ではない。再開は統括・運営者が決める）。
**取りに行く前に門（関所）がある。** 確認・判定・運営者の承認がそろっていない相手（未確認・承認がまだ）には、取りに行かない。
役所は数か月で消すので、**消えたものが残っているのが値打ち。**

いま5系統ある。

| | 何を見ているか |
|---|---|
| 大型店 | 大規模小売店舗立地法の届出（大阪・兵庫）。公開中 |
| 街頭窃盗 | 警察の統計。公開中 |
| 競売・公売 | 裁判所と役所の公告。公開中 |
| 開発系 | 開発許可・受付簿。非公開 |
| 住宅系補助金 | これから |

ほかに、鉄道の遅延証明書（民間）と保健所の営業許可を集め始めたが、いまは止めている。

## いまの状態で、知っておいてほしいこと

- **呼び名。** 最終の判断は**運営者**。方向とアイデアは**統括**（この1枚を受け取る側）。
  監査と第二意見は**参謀**（クラウド参謀・PC参謀）。手を動かすのは**各サイトの担当**（大型店日報ちゃん など）。
- **商業施設のフロアマップ。** 1施設（阪急西宮ガーデンズ）から、2026-09-25 に
  「ロボットによる取得不可」と回答があった。その施設へは 2026-09-24 から取りに行っていない
  （それより前、9/21〜24 に4回取った分の扱いは、取得を止めたこととは別に決める）。
- **同じ相手へ、同じ日に、2つの置き場から行かない仕組み**（予約台帳）は、実装・試験中。本番ではまだ使っていない。
- **民間の公開Webを自動で観測することの一般的な法務**は、弁護士に相談している。答えはまだ出ていない。

## 守っている線（相談のとき、ここは動かせない前提）

- **氏名・住所・電話を出さない。** 法人だと**分かったときだけ**出す。
  分からなければ伏せる側に倒す。
- **1〜2件の数字は伏せる。** 例外は中身が法人だけのとき
  （守っているのは人なので）。**ただし個票を全部出しているサイトだけ**——
  升しか出さないサイトで選り分けると、伏せ字が「ここに人がいる」の印になる。
- **評価しない。** 「◯◯市は遅い」「狙い目」「急いだほうがいい」は書かない。
  **自治体から取って自治体を評価すると、取得が止まる。**
- **推測しない。** 書いていないことを埋めない。
- **robots が拒否したら取りに行かない。回り込まない。**
  同じ相手に1日2回行かない。
- **迷ったら止まる側に倒す。**

## いちばんよく踏む間違い（指摘のとき、この形を疑ってほしい）

- **名乗りが事実の主張になる。** 「最終更新」がこちらの作業日だった、
  「伏せた」が伏せるものの無いものだった、など。**主語をこちらにする。**
- **「0件」は、その道を1回も通っていないときにも出る。**
- **「返ってきた」は「見つかった」ではない**（200 でも中身が空のことがある）。
- **点では持てない日付を、点で持つ。** 多くても1日1回しか見ていないので、
  「変わった日」「消えた日」は**区間**でしか分からない。
- **全部が同じ理由で失敗したら、相手ではなく自分を疑う。**

## お金の考え方

- 写した一覧（役所が出したもの）は**無料**。権利を主張しない。
- **横断して揃えた一覧**は、集め方と並べ方がこちらの労力。申請制でよい。
- **観測して作ったもの**（消えた日・変わった区間・期間の分布）は
  **こちらが作ったもの**。有料にしてよい。
- **役所から消えたものは、後者に寄る**（もう役所からは取れない）。
- 守りに力を使わない。**「盗めない」ではなく「コピーしても追いつけない」。**

## 聞きたいこと

**「その設計、穴ないか」。** とくに、

- 5年後に作りたくなるデータの**欄が、いま存在するか**
- 無料と有料の境界が、**言っていることとやっていることで食い違っていないか**
- **個人情報が、1件ずつでは伏せているのに、並べると出る形**になっていないか
- 文章が**事実と解釈を混ぜていないか**

**そして、こちらが聞かなかったことで気になったものがあれば、書いてください。**
**数は決めません。あるだけ、理由をつけて。**

## 埋めるときの決まり（**ここを外すと、外の目が誤診する**）

- **「未測定」と「0」を混ぜない。** 0件は、**その道を1回も通っていない**
  ときにも出る。測っていないなら「未測定」と書く。
- **「取れる」と「取っていい」を分ける。** robots が拒否していれば、
  技術的に取れても**取らない**。
- **推測を数字の欄に書かない。** 「たぶん年100件くらい」は気になる点へ。
- **消えた日は区間。** 「9/21 に消えた」ではなく
  「9/20 と 9/21 のあいだに消えた」。毎日1回しか見ていない。
- **測ったのが誰かを書く。** こちらが見たのか、人から聞いたのか、
  資料にそう書いてあったのか。**名乗りは事実の主張になる。**
- **「対象地域」と書かない。「調査対象地域」と書く。**
  2026-09-20、運営者の言い換え。**欄の名前そのものが名乗りになる。**
  「対象地域：◯◯市」は「その市を網羅している」と読まれる。
  **いま調べているのがそこ、というだけ。**

## 向こうからの提案は、**閉じずに受ける。ただし持ち帰る**

2026-09-20、運営者の指摘。**「聞きたいのはこれだけ」は、もったいない。**

**証拠がこちらに在った。** その日いちばん効いた指摘は、**3つとも聞いていないこと**だった。

    落とした理由の数字が古くなっていた       ← 聞いていない
    落とした理由が**地域依存に変わっていた**   ← 聞いていない
    落とした理由が**全国論としては古い**       ← 聞いていない

**聞いた2つより、聞かなかった3つのほうが効いた。**
こちらは中にいるので、**何を聞いていないかが自分では見えない。**

### 数にも上限をつけない（2026-09-21・**同じ間違いの3例目**）

    ❌ 「聞きたいのはこれだけ」        **答えの範囲**を閉じた
    ❌ 「気になったものがあれば」       **出す／出さない**を相手に預けた
    ❌ 「1〜3件」                      **数**を閉じた  ← **これも同じ形**

**3件しか思いつかないと思っているのは、こちら。**
4件目がいちばん効くかもしれない。**上限は、こちらの想像の上限でしかない。**

**下限だけ決める。** 「1つは必ず。良いと思えなければ『いまは無い』と書いて」。
**上は開けておく。**

### だから「閉じる」のをやめて、「下限」にする

    ❌ 「聞きたいのはこれだけ」   答えの**範囲を閉じる**
    ✅ 「これは**必ず**答えて。そのうえで気づいたことがあれば、あるだけ」   **下限だけ決める**

**濃さは下限で保つ。** 何も絞らずに「どう思う？」と聞くと、**意見が増えるだけ**に戻る。

### 受けるときの決まり（**ここを外すと、外の目が中の人になる**）

**① 提案は「調べ先の候補」。事実ではない。**
「◯◯という制度がある」は一次情報の話で、**頼まないことの側**。
**必ずこちらが原典で確かめてから台帳に入れる。**
確かめるまでは**「向こうが言った／こちらは見ていない」と分けて書く。**

**② 採否を報告しない。**
提案した側は、その案に肩入れする。**次から「自分の案がどうなったか」を気にして、
中立に穴を探さなくなる。** 同期そのものが仕事になるのは、前から書いてあるとおり。

**③ 提案は、必ず形に落としてから計画に入れる。**
向こうの文章のまま貼らない。**おまけの欄（題材・調査対象地域・測った日…）に
落とし直すと、「未測定」がどこかが見える。**

**④ 落としたものの一覧を先に渡す。**
渡さないと、**こちらが既に落としたものを提案してくる。**
渡せば、**落とした理由の賞味期限のほうを見てもらえる。**

## 「調査」を分けるとき、線は **測る／評価する**

「調べるのを頼む」と言うとき、**2つがくっついている。**

    **測る**    件数・消え方・更新の頻度・取り方・robots・規約
    **評価**    蓄積する値打ち・誰が使うか・既に誰かやっていないか

**測るほうは頼まない。** 理由が3つある。

1. **一次情報に自分で当たるのが、この事業の芯。**
   人から聞いた数字を台帳に入れたら、**ほかのまとめサイトと同じ**になる。
2. **robots と規約は、自分で見ないと守ったことにならない。**
3. **測っていない数字は、あとで区別がつかなくなる。**
   「未測定」と「0」を混ぜないのと同じ話（上）。

しかも**測るのはこちらが安い。** 取りに行くのは GitHub Actions の
ただの Python で、**Claude の枠を1ミリも使わない。**

**評価のほうは頼む。** とくに**「既に誰かが横断していないか」**は、
うちが取りに行く対象ではない（公開サービスの話）ので、外に出せる。

### 順番を逆にすると、測る手間が減る

    ❌ 測る → 外の目に評価してもらう → 「既にあるサービスでは？」
    ✅ 先に「既にある？」を聞く → 残ったものだけ測りに行く

取りに行くのは**5秒あけて1本ずつ**なので、時間がかかる。
**落とせる案を先に落とすと、そのぶん早く進む。**
「落としたもの」は理由つきで `docs/keikaku.md` に残す。

## 結論が食い違ったときが、いちばん値打ちがある

外の目と中の担当（このリポジトリの担当。2026-09-20 当時の呼び名は「統括」）で答えが割れたら、
**どちらかが間違っているのではなく、見ている軸が違う。** そこが検討点になる。

    外の目    「事業としての値打ちはまだ弱い」

**どちらも正しいことがある。** 割れたら、**運営者が決める。**

## 3件を並べて分かること

**聞き方が、案の熟し具合でちがう。**

    E      **測った数字を全部出す**       → 「無いのか、あるのか」（存在の確認）
    解体   **全部「未測定」のまま出す**   → 「自治体の名前を挙げて」（一覧）
    停電   **捨てた仮説を先に書く**       → 「どこが、何年分」（絞り込み）

**熟していない案ほど、聞くことが「名前」になる。**
熟した案ほど、聞くことが「有無」になる。

そして**3件とも「頼まないこと」を書いた。** E だけ「数字は全部こちらが測ります」、
解体と停電は**「件数を数えること」も頼まない。**
**測る手を渡さないのが、この事業の芯だから。**
