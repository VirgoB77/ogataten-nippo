# 取得可否確認（preflight）

新しい取得元を「取ってよいか」判断するための、**最小の確認**の置き場（2026-09-27・統括判断）。
**本番の取得ではない。** 通信を出すのは門（`common/kado.py` の `Kado.kakunin`）だけ。

| 置き場 | 中身 | 書くのは |
| --- | --- | --- |
| `cards.json` | 何を見るか（一覧・詳細の URL、確かめる語） | PC参謀（統括が確かめる） |
| `approvals/<許可ID>.json` | 許可（発行から24時間・1回だけ） | **運営者だけ** |
| `records/<source_id>/` | 見た結果（1回1ファイル。上書きしない） | 門（手で押す workflow） |

相手（source）の基本と担当の役割は `data/ref/aite-daicho.json` の `preflight` にだけ書く（ここには重ねない）。

## 1回で出すもの

- robots.txt：1本
- 一般公開の一覧：1本
- 一般公開の詳細：1本（カードに決め打ちか、一覧の中の型に合う最初のリンク）

GET だけ。見出しは名乗り（User-Agent）だけ。ログイン・POST・トークン取得・CAPTCHA の突破はしない。
同時1本、5秒以上（許可の秒数と robots の Crawl-delay の長いほう）あける。**転送は辿らない。**
拒否・認証・CAPTCHA・転送・門の想定外が出たら、**残りを出さずに止まる。**

同じ相手・同じ日本時間の日の枠（今日の控え・予約台帳）は、本番の取得と共有する。

## 許可は、ほかの承認とは別

**取得可否確認の許可 ≠ 本番の取得承認（`data/ref/shounin/`）≠ private 長期保存の承認 ≠ 公開の承認 ≠ 商品化の承認。**
この許可があっても、本番の門は今までどおり止まる。
